# TidyShot broad code review, 2026-11-06

TidyShot is a private macOS 26 menu-bar screenshot and screen-recording app for one user: about 36k lines of Swift under TidyShot/ and about 47k lines of Swift Testing tests under TidyShotTests/ (2380 tests in 197 suites, all passing on main today), Swift 6 language mode with MainActor as the default isolation, App Sandbox and Hardened Runtime, SigV4 uploads to the user's own S3-compatible bucket, credentials in the login Keychain, a tidyshot:// URL scheme on by default with silent captures off by default, and Clop reached over a CFMessagePort. Every module was reviewed read-only by independent agents under four lenses (correctness; security and privacy; concurrency and resource lifecycle; robustness and data loss), plus cross-cutting audits of sandbox and privacy posture, test-suite quality, the known flaky test and architecture. Findings were deduplicated per module (cap 10), then verified adversarially: medium and above as filed went to a code-tracing verifier and a challenger told to refute the finding and re-rate its impact; lows as filed went to the challenger alone. A finding is confirmed only when every verifier confirmed it, plausible when they split. 197 findings were examined: confirmed 5 medium, 105 low, 1 info; plausible 7 medium, 8 low; 65 refuted; 6 info-level not verified. Nothing was built or run. Confirmed low findings in the product code have their own section after the medium findings; the test-suite and architecture ones are under their own headings below.

## Medium findings (confirmed)

### 1. A redaction drawn after a blur or pixelate leaks the hidden pixels into the earlier effect's margin

**Where:** [RedactionTileCache.swift:67](TidyShot/Editor/Rendering/RedactionTileCache.swift:67)

**What:** `keys(for:)` builds `beneath` from `0..<index`, so a blur or pixelate created before a redaction never gets that redaction composited under it; its tile is rendered from the raw base over a sample rect that reaches ceil(3*sigma) px past its own rect ([RedactionRenderer.swift:62](TidyShot/Editor/Rendering/RedactionRenderer.swift:62)), and `directlyBeneath` (:181) uses the same key. The flattener draws each tile over its own rect only, so the blur halo outside the redaction keeps a Gaussian of the covered pixels, and a pixelate cell straddling the redaction's edge averages them the same way. Effects stay in creation order (there is no z-order or reorder feature), so spec 2.6's "never smears" holds only when the redaction comes first; the `uncovered` case of `blurNextToRedactSamplesRedactInMargin` ([RedactionRendererTests.swift:229](TidyShotTests/RedactionRendererTests.swift:229)) is exactly the tile the reverse order produces, and no test covers a blur created before a redaction.

**Trigger:** On a 2x capture, blur a whole panel (8 pt, sigma 16 px, reach 48 px), then draw Redact over an API key inside it. The export shows the key line as black and a blurred band around it that carries the key's glyph colours; coloured tokens or error text show in the halo, and with a small blur the strokes near the edge can partly be deconvolved.

**Fix:** Make redactions independent of creation order: in `keys(for:)` and `directlyBeneath`, give every blur and pixelate all redactions whose rect meets its sample rect, whatever their index, plus the earlier non-redact effects as today, and composite those redactions in `RedactionRenderer.composite` (:91) before the earlier tiles. Add an export test with the blur created before the redaction.

**Verification:** confirmed by the trace and the challenger. The trace rated it low, the challenger medium; the verified severity is medium.

### 2. Copy Image puts the unredacted original on the clipboard without taking clipboard ownership, so a later redaction does not replace it

**Where:** [AppCoordinator+RecordActions.swift:97](TidyShot/App/AppCoordinator+RecordActions.swift:97)

**What:** Spec 2.6's clipboard rule swaps the edit onto the clipboard through `clipboardOwner`: `replaceClipboardIfStillOriginal` ([AppCoordinator+Editor.swift:436](TidyShot/App/AppCoordinator+Editor.swift:436)) replaces only while `EditorClipboard.shouldReplace` holds, that is while the owner's change count equals the pasteboard's. The copy paths that set an owner are `save` ([AppCoordinator+Save.swift:73](TidyShot/App/AppCoordinator+Save.swift:73)) and the editor's Copy (`editorCopy`, [AppCoordinator+Editor.swift:457](TidyShot/App/AppCoordinator+Editor.swift:457)), plus the failed-save fallback `keepFailedEditOnClipboard` (:237) and the replacement itself (:444). `copyImage(recordID:)`, which the card, the pin and the Recent Captures row all call, writes the same PNG and TIFF but discards the change count `clipboard.copy` returns and never sets an owner, so it moves the count past the one `save` set. [CoordinatorEditorSaveTests.swift:853](TidyShotTests/CoordinatorEditorSaveTests.swift:853) covers only the save-then-edit case.

**Trigger:** Capture a window showing an API key with default settings (the image is copied and the owner set at count 1). Click Copy Image on the card: count 2, owner unchanged. Annotate, blur the key, Cmd-S: `shouldReplace` fails, the clipboard still holds the unredacted PNG, and the paste into Slack is the original.

**Fix:** In `copyImage(recordID:)`, store the returned change count as `clipboardOwner = EditorClipboard.Owner(recordID: recordID, changeCount: ...)`, as `editorCopy` does. Better, route both through one helper that copies a capture's image and takes ownership, so the next copy path cannot drift.

**Verification:** confirmed by the trace and the challenger, both at medium.

### 3. Auto mode: Done (or a stream stop) drops the newest step the screen already shows

**Where:** [ScrollCaptureSession.swift:300](TidyShot/Scrolling/ScrollCaptureSession.swift:300)

**What:** In auto mode `take(_:)` stores each frame as `latestFrame`, bumps `frameSerial` and returns at :300 without `engine.add`; only `integrate()` (:243) stitches, called from [AutoScrollDriver.swift:90](TidyShot/Scrolling/AutoScrollDriver.swift:90) once `FrameSettler` reports about 150 ms of quiet, polled every 50 ms. `done()` (:186) cancels the driver, sets `.finishing`, stops the source and drains `readTask`; from then on only a frame still in the one-deep stream buffer reaches the engine, a frame already read but not yet integrated is discarded, and `engine.finish` (:195) commits only the last accepted frame. Once the page goes still SCK sends only idles, so the unintegrated frame is the usual state. `streamStopped()` (:325) has the same gap. Manual mode does not, because every frame goes to `engine.add`; `doneStopsPostingAndFinishesWithTheImage` only checks that the outcome is `.image`.

**Trigger:** Auto-scroll posts a step, the page moves and goes still, and within about 200 ms, before the settler fires, Tim presses Done or the Capture Scrolling shortcut. The saved image is one step short of what the panel showed (about 200 to 600 px), silently, and the after-capture action runs on the short image.

**Fix:** Track the serial of the last frame handed to the engine (in `integrate` and the manual path of `take`). In `done()`, after `await readTask?.value` (:193) and before `engine.finish`, call `engine.add(latestFrame)` if its serial is newer. In `streamStopped()`, add it straight before `engine.finish` (:333) with no `readTask` await: it is called from inside `read()` at [ScrollCaptureSession.swift:280](TidyShot/Scrolling/ScrollCaptureSession.swift:280), which is `readTask` itself, so awaiting there would wait on itself. A lost or still result commits nothing, so the extra add is safe. Extend the Done test to compare the stitched height with the world offset.

**Verification:** confirmed by the trace and the challenger, both at medium.

### 4. URL-triggered capture-window and self-timer take the first click with no arming, so the second click of a double-click captures a window with the sender's action

**Where:** [AppCoordinator+Capture.swift:201](TidyShot/App/AppCoordinator+Capture.swift:201)

**What:** The URL handler routes capture-window and self-timer to `captureWindow` and `captureSelfTimer` with no URL flag ([URLCommandHandler.swift:187](TidyShot/URLScheme/URLCommandHandler.swift:187) and :191). `captureWindow` (:19) goes through `runSelection` (:201) to `selector.select(mode:...)` at :208; `captureSelfTimer` (:186) calls `selector.select(mode: .selfTimer, ...)` directly at [AppCoordinator+Capture.swift:189](TidyShot/App/AppCoordinator+Capture.swift:189). `select` hardcodes `armed: true` at [SelectionController.swift:40](TidyShot/Selection/SelectionController.swift:40); only `captureAllInOne` (:39, `armed: !fromURLCommand`) got spec 2.9's fix. In window mode `present()` highlights the window under the pointer at once, `acceptsFirstMouse` is true ([SelectionView.swift:92](TidyShot/Selection/SelectionView.swift:92)), and one press and release resolves to `.window` ([SelectionOutcome.swift:30](TidyShot/Selection/SelectionOutcome.swift:30)). `capturesWithoutSelection` ([URLCommand.swift:68](TidyShot/URLScheme/URLCommand.swift:68)) leaves capture-window, self-timer and scrolling outside the silent-capture gate, so they run with silent captures off and the sender's action. The no-rect scrolling path (:102) also opens its panel key on the picked window with no ready timeout. `SelectionViewArmingTests` covers only the All-in-One preselect.

**Trigger:** A same-user process, or a web page once Chrome's "Always allow" is ticked, opens `tidyshot://capture-window?action=copy` while Tim double-clicks in Mail. The overlay appears between the clicks, the second click picks the Mail window, and its image lands on the pasteboard, or with action=upload (or the default Upload only) in the public bucket with the URL on the clipboard, all with silent captures off.

**Fix:** Give `captureWindow`, `captureSelfTimer` and the no-rect `captureScrolling` a `fromURLCommand` flag in `URLCommandTarget`, as `captureAllInOne` has, and pass `armed: false` to `select(mode:...)` so the first press only arms. For URL scrolling, avoid `makesPanelKey` and add a ready timeout. Add coordinator and `SelectionView` arming tests for window mode.

**Verification:** confirmed by the trace and the challenger. The trace rated it low, the challenger medium; the verified severity is medium.

### 5. A disarmed All-in-One URL rect still captures on a single click on its toolbar, whose position the sender chooses

**Where:** [SelectionView.swift:551](TidyShot/Selection/SelectionView.swift:551)

**What:** An All-in-One URL rect opens disarmed so that a Return, or the second click of a double-click begun elsewhere, cannot capture it; `allInOneMouseDown` (:461) reads `wasArmed` (:463) for that. The toolbar skips the rule: `toolbar.onAction` (:551 to :556) sets `keyCaptureArmed = true` and calls `fireAllInOne(action)` in the same handler, with no check of the previous state. A press on Capture, Fullscreen, Scrolling or Timer is tracked by the NSButton itself, which fires `onAction`, so `allInOneMouseDown` never sees it; the toolbar's empty `mouseDown` override at [AllInOneToolbar.swift:89](TidyShot/Selection/AllInOneToolbar.swift:89) only swallows presses on its background, and `acceptsFirstMouse` is true (:91). `beginAdjusting(armed: false)` (:442) still calls `layoutToolbar()`, and [AllInOneToolbarPlacement.swift:15](TidyShot/Selection/AllInOneToolbarPlacement.swift:15) puts the toolbar at a deterministic spot (centred, 8 pt below the rect, fixed fallbacks), so the sender's x and y choose where the buttons land. `SelectionViewArmingTests` covers Return, a double-click inside the rect, arrows and a new rect, not a toolbar click.

**Trigger:** URL commands are on by default. A same-user process reads `NSEvent.mouseLocation` (no permission needed) and, on the first click of a double-click, opens `tidyshot://all-in-one?x=..&y=..&width=..&height=..&action=copy` with the rect placed so Fullscreen sits under the pointer. The second click lands on Fullscreen, the display is captured to the clipboard and the process reads it; a web page can do the same once the browser's always-allow is ticked. This bypasses the silent-capture gate.

**Fix:** While `keyCaptureArmed` is false, a toolbar action only arms and does not fire. Or ignore presses within `NSEvent.doubleClickInterval` of the overlay appearing, or with `clickCount` above 1 on the first press. Add a `SelectionViewArmingTests` case for a toolbar click on a disarmed rect.

**Verification:** confirmed by the trace and the challenger, both at medium.

## Low findings (confirmed)

Each was confirmed by an adversarial verifier; the verifier's narrowing is reflected in the text.

### App coordinator: capture, quit and launch

- **[AppCoordinator.swift:476](TidyShot/App/AppCoordinator.swift:476)** Quit does not wait for an image save in progress. What: `holdsQuit` checks only unsaved editors and the recording phase, never `isCapturing` or saves in flight, so `applicationShouldTerminate` returns `.terminateNow` during the detached encode. Trigger: Quit, Restart or Log Out while a 40,000 px scrolling capture encodes; no file, record or clipboard copy survives. Fix: count image saves in flight and hold the quit until the count is 0.
- **[AppCoordinator+Overlay.swift:58](TidyShot/App/AppCoordinator+Overlay.swift:58)** Pointer-screen lookup misses a screen's top row. What: three sites (here, [AppCoordinator.swift:387](TidyShot/App/AppCoordinator.swift:387), [AppCoordinator+Pins.swift:63](TidyShot/App/AppCoordinator+Pins.swift:63)) use `frame.contains(NSEvent.mouseLocation)`, which excludes `maxY`; `CaptureEngine.display(under:)` converts to CG and gets it right. Trigger: pointer on a display's menu bar. Card placement is affected only when not on the default `.capture`; URL rects and pin centring still go wrong. Fix: one CG-based helper, or `NSMouseInRect(..., false)`.
- **[AppCoordinator.swift:306](TidyShot/App/AppCoordinator.swift:306)** A second instance wipes the first one's work files. What: `start()` deletes tmp/Clop and tmp/Trim, sweeps multipart/ and adopts pending/ and recording leftovers with no other-instance check; Debug and Release share `io.tky.tidyshot`. Trigger: Run from Xcode while the installed app records, trims or waits on Clop; history.json then ends up with whichever process wrote last. Fix: detect another running instance in `applicationWillFinishLaunching` and hand off, or set `LSMultipleInstancesProhibited` and give Debug its own bundle id.
- **[AppCoordinator+Capture.swift:286](TidyShot/App/AppCoordinator+Capture.swift:286)** Late Capture Text overwrites newer clipboard contents. What: the capture lock is released before recognition, then `copyText` calls `setString` with no change-count or sequence check. Trigger: the first recognition after restart (about 24 s) finishes after a screenshot copied the image, or two Capture Texts finish out of order. Fix: record the change count at capture time and set the text only if it still matches; otherwise just post the notice.
- **[AppCoordinator+Overlay.swift:88](TidyShot/App/AppCoordinator+Overlay.swift:88)** Restore Closed Overlay can lose its entry. What: `popRestorable` removes the id before the thumbnail await, and the post-await guard returns without putting it back. Trigger: during a slow thumbnail read, Delete on that row then Cancel at the alert; `deletingIDs` fails the guard and the card is not restorable until it closes again. Fix: peek before the await and pop once the card is shown, or push the id back on guard failure.
- **[AppDelegate.swift:76](TidyShot/App/AppDelegate.swift:76)** Edits made during a held quit are discarded silently. What: the held quit runs `reviewEditorsBeforeQuit()` once, awaits `finishRecordingForQuit()` while events still flow, then replies true without rechecking `hasUnsavedEditors`. Trigger: quit during a recording with a clean editor open, then add an arrow while the recording saves. Fix: re-check unsaved editors and review again after `finishRecordingForQuit()` returns.
- **[AppCoordinator.swift:319](TidyShot/App/AppCoordinator.swift:319)** A set-aside history makes the launch sweep delete all multipart state. What: sweep states come from `history.records` right after `load()`; when `load()` sets aside a corrupt history.json and starts empty, `sweepRemovals` removes every sidecar and kept Clop copy. Trigger: history.json undecodable after a disk-full write during a 2 GB multipart upload; restoring it later restarts the upload from zero. Fix: skip the multipart sweep on a launch where `load()` set the file aside.

### App coordinator: save, upload, delete and recovery

- **[AppCoordinator+Editor.swift:414](TidyShot/App/AppCoordinator+Editor.swift:414)** Failed DELETE of a superseded object is only logged. What: `deleteSupersededObjects` logs a failure with no notification or card state, and DELETEs are signed with the credentials stored now, so after a bucket and key change they always fail. Narrow case. Trigger: upload to bucket A, switch to bucket B, redact and re-upload; the unredacted L1 stays public, and a retention prune later drops the ref. Fix: notify with the old link, show it on the card, retry leftover refs, and do not prune records holding them.
- **[AppCoordinator+Upload.swift:658](TidyShot/App/AppCoordinator+Upload.swift:658)** A cancelled upload's reserved key is lost. What: `.uploaded` clears `pendingObjectKey` and overwrites `objectLocation` when the location changed, and `.cancelled` overwrites an earlier reserved key; `EditorUploadPlan.applyingFailure` handles this correctly. Trigger: delete mid-upload to A, the DELETE fails offline, keep the row, switch to B and Retry; K1 at A is never deleted. Fix: in both branches, append the old reserved key to `supersededObjects` before clearing or overwriting it.
- **[AppCoordinator+Recovery.swift:30](TidyShot/App/AppCoordinator+Recovery.swift:30)** Crash-orphaned unmuted recording loses its upload block. What: the "Sound not muted" mark exists only on the record; `adoptPendingFiles` builds a record without `unmutedIntervals`, then the mute log is swept. Trigger: mute fails (`.notMuted`), file moves to pending/, app is killed before `history.add`; relaunch adopts it as ordinary and it can be uploaded with the sound in it. Fix: pass mute logs to `adoptPendingFiles` and set `unmutedIntervals` or re-run muting; keep logs that have a pending file.
- **[AppCoordinator+Upload.swift:708](TidyShot/App/AppCoordinator+Upload.swift:708)** Objects from failed or retried single PUTs are not recorded. What: each attempt reserves a fresh HEAD-checked template key, and the coordinator learns only the final key. Trigger: a PUT times out after S3 stored it; attempt 2 or a later Retry writes another key, and Delete leaves the first object public. Fix: report each reserved key to the coordinator, persist them on the record, and delete them as superseded objects.
- **[AppCoordinator+Save.swift:130](TidyShot/App/AppCoordinator+Save.swift:130)** TIFF fallback empties the clipboard and reports success. What: when the PNG encode fails, `copyOnly` calls `copy(tiffData:)` with no nil check, which clears the pasteboard, then posts "Image copied". Trigger: a `tidyshot://` area capture with action=copy where both encoders fail. Fix: leave the pasteboard alone when the TIFF is nil and post "Could not copy image"; same wording fix for the editor and save fallbacks.
- **[AppCoordinator+Delete.swift:75](TidyShot/App/AppCoordinator+Delete.swift:75)** Delete leaves a dead link when the local-file step fails. What: objects are DELETEd first without updating the record; if `saveLocation.remove` throws and the user cancels, `uploadState` stays `.uploaded`. The same applies when a later group's DELETE fails. Trigger: delete an uploaded capture whose file is in a previous save folder, removal is denied, user clicks Cancel; Copy URL now returns 403/404. Fix: update the record (clear upload state and object refs) right after the DELETEs succeed.

### App coordinator: recording and trim

- **[AppCoordinator+Recording.swift:784](TidyShot/App/AppCoordinator+Recording.swift:784)** Overlapping recording saves open two folder panels. What: `ensureFolder()` opens a new `NSOpenPanel` whenever `currentURL` is nil, and each save reads only its own answer. Trigger: no folder set, a GIF conversion still saving while a second recording stops; pick a folder in one panel, dismiss the other, and that recording goes to pending/ with "No folder was chosen". Fix: share one in-flight chooser task in `SaveLocation`, or re-read `currentURL` when `ensureFolder` returns nil.
- **[AppCoordinator+Trim.swift:68](TidyShot/App/AppCoordinator+Trim.swift:68)** Trim download has no free-space check. What: `downloadAndPresentTrimWindow` downloads to tmp/Trim without a room check, unlike the drag-out download, which calls `DragDownloadRule.hasRoom`. Trigger: open Trim on a large upload-only recording with the disk nearly full; a concurrent recording and history.json writes fail. Fix: check `hasRoom` against `record.byteCount` before downloading, and abort if received bytes far exceed it.
- **[AppCoordinator+Recording.swift:529](TidyShot/App/AppCoordinator+Recording.swift:529)** Area is not size-checked after clipping to the fresh display frame. What: the 32x32 pt minimum runs only at selection; after the count-in the area is intersected with the current frame and not re-checked. `RecordingConfiguration.make` already handles a null rect, so impact is small. Trigger: a display shrinks during the count-in; the recording fails generically or records a sliver the start would refuse. Fix: guard `isLargeEnough(area)` after the intersection and post the refusal.
- **[AppCoordinator+Recording.swift:169](TidyShot/App/AppCoordinator+Recording.swift:169)** A record-screen URL start skips the prompt-lock check when its Task runs. What: `startRecording` checks synchronously and then starts an unstructured Task that never re-checks; `askingPermission` holds one value. Trigger: `tidyshot://record-screen` arrives while camera access is requested from Settings; both prompts show, and the first answer clears `askingPermission` while the other is still up, so a capture hotkey can screenshot it. Fix: re-check at Task start, and treat `urlRecordingStartPending` as an open prompt.
- **[AppCoordinator+Recording.swift:496](TidyShot/App/AppCoordinator+Recording.swift:496)** Fresh display frames are converted with a stale primary height. What: `primaryHeight` is read before the count-in and used after `loadContent` for area, window and extras placement, while `visibleFrame(forDisplayID:cgFrame:)` re-reads the screen. Trigger: docking during the count-in changes the primary from 982 to 1080 pt; the control panel and webcam bubble sit 98 pt off. Fix: re-read `primaryHeight` after `loadContent` returns.

### S3 destination and signer

- **[S3DestinationConfig.swift:160](TidyShot/Upload/S3DestinationConfig.swift:160)** Signed host for an IPv6 endpoint likely lacks brackets. What: `hostHeader` uses `url.host()`, which the verifier believes strips the brackets (not checked at runtime), while URLSession sends `Host: [::1]:9000`; validation accepts the endpoint. Trigger: endpoint `http://[::1]:9000` for local MinIO returns 403 SignatureDoesNotMatch. Fix: re-bracket a host containing ":" or use `URLComponents.percentEncodedHost`.
- **[S3DestinationConfig.swift:152](TidyShot/Upload/S3DestinationConfig.swift:152)** An endpoint path is dropped silently. What: `objectURL` replaces `percentEncodedPath` with the object path, and `validationError` checks only scheme and host. Trigger: endpoint `https://nas.example.com/minio` with bucket `snap` sends requests to `/snap/key`; the proxy answers 404 or 403. Fix: reject a non-empty endpoint path in validation, or prepend it to both the URL and the signed path.
- **[MultipartXML.swift:62](TidyShot/Upload/MultipartXML.swift:62)** Numeric XML entities in ListParts ETags are not decoded. What: `unescaped` handles only the five named entities; MinIO writes quotes as `&#34;`, so listed parts never equal stored parts. Trigger: Complete returns InvalidPart for one of 32 parts; the recovery drops all stored parts and re-uploads all 32. Fix: decode `&#NN;` and `&#xHH;` before the `&` pass, or compare parts by number and size.
- **[ConnectionTester.swift:47](TidyShot/Upload/ConnectionTester.swift:47)** Connection test leaves its probe behind after an ambiguous PUT failure. What: any upload error returns `.uploadFailed` without `deleteProbe`; only the 403 case is tested. Trigger: S3 stores `tidyshot-probe-ab12cd34.txt` but the response times out; "Upload failed" shows with no leftover warning. Fix: on a retryable or non-cancelled URLError, call `deleteProbe` and attach its warning.
- **[Destination.swift:211](TidyShot/Upload/Destination.swift:211)** Permanent URLErrors are retried with backoff. What: `isRetryable` returns true for every URLError except `.cancelled` and four file codes, including ATS refusal, untrusted certificate, TLS failure, `.badURL`, `.unsupportedURL` and `.cannotFindHost`. Trigger: an `http://` endpoint fails with -1022 on all 6 attempts over about 60 s before the error shows. Fix: add a non-retryable set for those codes.

### Upload queue

- **[UploadQueue.swift:175](TidyShot/Upload/UploadQueue.swift:175)** Single-PUT retry reserves a new template key on every attempt. What: `objectKey(for:retryingHEADs:false)` runs inside the retry loop, so `reserveKey` draws and HEADs a new key each pass and `reservedKeys` is overwritten. Trigger: the PUT body lands, then the connection drops; with `{random}` K2 is uploaded and K1 stays public after Delete; with a fixed template the job HEADs its own object, ends in `keyCollisionsExhausted`, and Retry fails the same way. Fix: reserve the key once per job and re-PUT it.

### URL scheme, Clop and naming templates

- **[TemplateExpander.swift:117](TidyShot/Output/TemplateExpander.swift:117)** A `{counter}`-only template counts as collision-guarded but retries the same key. What: `hasCollisionGuard` treats `{counter}` like `{random}`, but the counter is fixed in the job's context (0 on resume), so all five `makeKey` calls give one key. Trigger: `shots/{counter}` after the counter resets while `shots/1.png` exists; every upload fails with `keyCollisionsExhausted`, and Settings shows no warning. Fix: count only `{random}` as a guard, or vary the key per attempt.
- **[ClopClient.swift:88](TidyShot/Upload/ClopClient.swift:88)** Concurrent Clop requests share one cached port, and the first to finish invalidates it. What: `CFMessagePortCreateRemote` returns the same port per name, and each call defers `CFMessagePortInvalidate`; image and video requests run on separate queues. Trigger: a screenshot's request completes while a recording's waits; the video request fails with -5 and the recording uploads unoptimised. Fix: release without invalidating, serialise requests, or use an uncached port per request.
- **[ClopOptimiser.swift:188](TidyShot/Upload/ClopOptimiser.swift:188)** A Clop reply path ending in "." deletes tmp/Clop. What: `removeConvertedOutput` checks only that the parent resolves to the work directory; "<work>/." passes and `removeItem` removes the directory (confirmed by a standalone probe). Needs a buggy or hostile port holder. Trigger: an image reply with that path while a video work copy is in flight. Fix: require the resolved path to be strictly one level inside the work directory and reject "." and ".."; add tests.
- **[TemplateExpander.swift:50](TidyShot/Output/TemplateExpander.swift:50)** `{random:N}` with a non-ASCII digit gives 64 characters. What: the regex `\d` matches any Unicode digit, `Int(String)` parses only ASCII, and the fallback is the upper bound. Trigger: `shots/{random:８}` with a fullwidth 8 validates and yields 64-character keys. Fix: use `/random:([0-9]+)/` so validation reports it as an unknown token.
- **[URLCommandHandler.swift:104](TidyShot/URLScheme/URLCommandHandler.swift:104)** URLs arriving during the launch-queue drain run ahead of queued ones. What: `ready()` sets `isReady` and then awaits each queued item, including an interactive capture; new URLs see `isReady` and run immediately. Trigger: cold launch queues capture-area then show-desktop-icons; hide-desktop-icons during the selection runs first, so icons end up shown. Fix: set `isReady` after the drain, or start queued captures in their own Task.
- **[FileNamer.swift:39](TidyShot/Output/FileNamer.swift:39)** File names are not capped at 255 bytes. What: `sanitize` replaces "/" and ":" and trims, but nothing limits length with the extension and the " N" suffix from `uniqueURL`. Trigger: a long prefix plus `{random:64}` near 250 bytes; saves throw ENAMETOOLONG and recordings fall back to pending/. Fix: truncate on a Character boundary to leave room for extension and suffix, or validate the expanded length in Settings.
- **[URLCommandHandler.swift:211](TidyShot/URLScheme/URLCommandHandler.swift:211)** Refused URLs after launch post notices with no limit. What: only the pre-launch queue is capped (8); each parse failure or gate refusal NSLogs the full URL and posts an error notice, with no throttle or dedupe. Trigger: an allowed page loops `location.assign('tidyshot://bogus?'+i)` and floods Notification Center, burying real refusals. Fix: rate-limit or coalesce refusal notices and bound in-flight handle tasks.

### Output files and history
